# Дом Кино

Мобильное приложение резиденции: доступ, консьерж, умный дом и клуб.
React + Vite. Живёт на https://dom.talkmate.uz, а для отправки заказчику
собирается в один самодостаточный HTML-файл, который открывается на телефоне
без сервера и без интернета.

## Запуск

```bash
npm install
npm run dev           # localhost:5173, горячая перезагрузка
npm run build         # dist/ — обычная сборка, для сайта
npm run build:single  # dist-single/«Дом Кино.html» — один файл, для отправки
npm run preview       # посмотреть собранную версию
npm run deploy        # собрать и выложить на dom.talkmate.uz
```

Node 18+.

### Почему две сборки

Однофайловая версия удобна для пересылки, но для сайта не годится: JS вшит
в конец документа, и браузер не рисует ни строчки, пока не докачает все два
мегабайта. На нестабильной мобильной связи это белый экран, а оборвавшуюся
загрузку нечем ни повторить, ни закэшировать — приложение просто не
открывалось. Обычная сборка отдаёт разметку сразу (index.html весит около
килобайта), дальше идут отдельные файлы: до первой отрисовки нужно ~90 КБ
вместо полутора мегабайт, фотографии подтягиваются по мере надобности,
а при повторном заходе берутся из кэша.

## Как устроено

```
src/
  main.jsx              точка входа, читает настройки из адресной строки
  App.jsx               выбирает: демо-сценарии / вход / приложение

  theme/                палитры, шрифты, анимации, safe-area
    palette.js          светлая и тёмная темы, одинаковый набор ключей
    ThemeContext.jsx    useColors() — палитра, useTheme() — ещё и переключение
    safeArea.js         отступы под чёлку и жестовую полосу
    global.css          фон, прокрутка, поведение на телефоне
    fonts.css           Golos Text, Oswald, Cormorant Garamond локально
    animations.css      все @keyframes

  store/                состояние, разложенное по смыслу
    SessionContext.jsx  пройден ли вход, включён ли демо-режим
    NavContext.jsx      вкладка, экран, шторка, модалка, подсказки
    DataContext.jsx     данные жителя: двери, дом, консьерж, клуб, счета

  ui/                   набор компонентов: Button, Card, Switch, Icon,
                        Scene (фото), Photo (заглушка), MenuRow, Chips,
                        Field, Overlay (шторка и модалка), Toast

  layout/               оболочка приложения, таб-бар, шапки экранов

  screens/
    onboarding/         вход: заставка → телефон → код → квартира →
                        Face ID → разрешения
    demo/               список демо-сценариев и панель управления показом
    today/ access/ concierge/ home/ club/ profile/
                        вкладка + её внутренние экраны
    sheets/ modals/     реестры шторок и модальных окон
    routes.js           ключ экрана → компонент
    MainApp.jsx         собирает всё вместе
```

### Навигация

Четыре независимых слоя поверх вкладки:

```js
const { go, back, switchTab, openSheet, openModal, confirm, showToast } = useNav();

switchTab('club');                       // сменить вкладку
go({ key: 'space', data: { … } });       // открыть внутренний экран
openSheet({ key: 'pickTime' });          // шторка снизу
openModal({ key: 'success', title: … }); // модальное окно
showToast('Дверь открыта', { icon: 'check', tone: 'ok' });
```

Новый экран добавляется в два шага: компонент в нужной папке `screens/…`
и строчка в `screens/routes.js`. Данные из `go({ key, data })` приходят
компоненту свойством `data`.

### Тема

Цвета берутся только из палитры, ни один компонент не знает про режим:

```js
const c = useColors();
<div style={{ background: c.card, color: c.text, border: `1px solid ${c.line}` }} />
```

### Отступы под систему

Приложение занимает весь экран, поэтому сверху под него попадает чёлка,
а снизу — жестовая полоса. Все такие отступы — в `theme/safeArea.js`.
Нарисованного статус-бара нет: на телефоне его рисует система.

## Демо-сценарии

На заставке — кнопка «Демонстрация концепции» с шестью подготовленными
сценариями. Обычный вход: тап по заставке → любой номер из 10 цифр →
любой код, кроме `0000` → выбрать резиденцию.

Нужный экран можно открыть сразу через адресную строку:

```
?screen=Сегодня
?screen=Звонок домофона&theme=Тёмная
?accent=%23c0763a
```

Значения `screen`: Сегодня, Я еду домой, Цифровой двойник, Приватный сад,
Подготовить квартиру, Пригласить гостя, Звонок домофона, Закрытый показ,
Демо-режим. Список — в `screens/demo/scenarios.js`.

## Как открыть на телефоне

- **Файлом** — отправить `dist/Дом Кино.html` в мессенджер или AirDrop.
- **По Wi-Fi** — `npm run preview` и открыть на телефоне
  `http://<ip-компьютера>:4173` (IP: `ipconfig getifaddr en0`).
- **Как приложение** — в Safari «Поделиться» → «На экран «Домой»».
  Тогда приложение запускается без адресной строки, и отступы под чёлку
  и жестовую полосу начинают работать по-настоящему.

## Происхождение и правки

Собрано из экспорта дизайн-инструмента (`Дом Кино - автономный (3).html`):
один класс на 1700 строк с вызовами `React.createElement` разложен по
компонентам, состояние вынесено в контексты, стили — в палитру.

Что изменено по существу:

1. **Убран макет телефона.** Рамка устройства и нарисованный статус-бар
   (9:41, «остров», батарея) заменены на настоящие safe-area отступы.
2. **Не работал вход.** Кнопка «Продолжить» требовала 11 цифр, хотя «+7»
   вынесен отдельной меткой и подсказка показывает 10. Порог — 10 цифр.
3. **Тёмная тема ломала таб-бар.** Код читал `c.dark`, которого в объекте
   темы не было, — таб-бар оставался светлым, подпись активной вкладки
   сливалась с фоном. Поле добавлено в палитру.
4. **Поля ввода 16 px на сенсорных экранах** — иначе Safari масштабирует
   страницу при фокусе и обратно не возвращает.
